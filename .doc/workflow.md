# Prompt 生产工作流程

## 输入与输出

- 输入：`episodes/<episode-id>/brief.md`，以及它引用的 `series/<series-id>/` 事实资料。
- 输出：只写 `outputs/<episode-id>/video-prompt.md`。
- 结构：从 [输出模板](templates/video-prompt-template.md) 开始；不要在输出中保留模板占位符。

## 执行步骤

1. 确认目标 `episode-id`，阅读该集 brief，摘出时长、受众、必须出现的事实和禁止内容。若 brief 未指定时长，按讲清概念所需内容估计时长；不得超过 150 秒，也不要为了凑到 60 秒而删减必要解释。
2. 阅读 [比奇堡世界观与角色选角](bikini-bottom-setting.md)，先确定当集需要哪些经济功能，再从角色表中选角；再阅读 brief 引用的系列资料。
3. 先按[故事情节与类比机制](storytelling-mechanism.md)完成草稿故事卡：主角目标、可见压力、变化与未变化的条件、直觉误解、类比映射、纠正动作和迁移边界。先草拟至少两个因果相同、世界不同的类比场景，选择主题映射最准确、主角选择代价最清楚、删去概念名后仍能独立成立的那个。故事卡只用于生成检查，不写入交付文件。
4. 按模板写出完整故事、时间轴和连续分镜。让每个镜头推动一个明确的叙事或理解动作，并让角色行动展示其经济功能；先让观众看见关系，再命名术语或公式。
5. 检查所有事实与素材引用是否来自输入；对缺失信息标记“待确认”。用故事机制的交付前自检确认类比没有跳步、没有把单一角色设为结论预设的反派，且已写出迁移边界。
6. 运行：

   ```bash
   node scripts/validate-video-prompt.mjs outputs/<episode-id>/video-prompt.md
   ```

7. 修复校验错误，再自行审核 brief 中的必须项、禁止项、角色连续性和故事机制自检。校验通过后才交付。

## 修改既有输出

只改用户指定集的输出文件。重新生成前先读取原文件，保留仍然符合最新 brief、系列资料和生成规则的内容；不要影响其他 episode 的输出。
